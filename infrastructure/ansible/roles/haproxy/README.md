# Описание роли: haproxy

Роль выполняет установку и настройку балансировщика нагрузки HAProxy для обеспечения высокой доступности сервиса Gitea (HTTP и SSH ). Роль работает в связке с `keepalived`, который управляет VIP на узлах прокси-слоя.

## Требования (Requirements)

* **ОС**: Ubuntu 22.04 (целевая ОС контейнеров).
* **Сетевая связность**: Узлы прокси должны иметь доступ к `gitea_servers` по портам 3000 (HTTP) и 22 (SSH).
* **Keepalived**: Для корректной работы отказоустойчивости на уровне L3 требуется предварительная или совместная настройка роли `keepalived`.

## Переменные роли (Role Variables)

### Глобальные переменные (из `group_vars/all/vars.yml`)

| Переменная | Описание |
| --- | --- |
| `gitea_vip` | Виртуальный IP-адрес (`172.20.0.20`), на котором HAProxy принимает входящий трафик. |
| `gitea_http_port` | Порт веб-интерфейса Gitea (`3000`). |

### Переменные инвентаря (из `inventory.ini`)

Роль динамически использует группу `gitea_servers` для формирования списка бэкендов в конфигурации.

## Техническая реализация (Architecture)

### 1. Обработка трафика (L4/L7)

Конфигурация в шаблоне `gitea.cfg.j2` разделяет потоки данных на два фронтенда:

* **Gitea Web**: Работает в режиме `mode http`. Принимает запросы на порту `3000`.
* **Gitea SSH**: Работает в режиме `mode tcp`. Принимает запросы на порту `2222` и проксирует их на стандартный SSH-порт (22) реальных узлов Gitea.

### 2. Алгоритм балансировки и HA

* **Режим работы**: Роль реализует схему **Active-Passive** для прикладного уровня. Трафик направляется на основной узел (`gitea-node-01`), а второй узел (`gitea-node-02`) помечен параметром `backup`.
* **Проверка состояния (Health Checks)**:
* Для HTTP используется `option httpchk GET /`, позволяющий HAProxy определять работоспособность самого приложения Gitea, а не просто доступность порта.
* При падении основного узла трафик автоматически переключается на `backup`-ноду.



### 3. Задачи (Tasks)

Основные этапы выполнения (`tasks/main.yml`):

1. Установка пакета `haproxy` через менеджер пакетов `apt`.
2. Развертывание шаблона конфигурации `/etc/haproxy/haproxy.cfg` (или инклюда в `/etc/haproxy/conf.d/`).
3. Включение и запуск службы `haproxy`.
4. Вызов обработчика (handler) для перезапуска сервиса при изменении конфигурации.

## Взаимодействие с другими компонентами

* **Keepalived**: Обеспечивает доступность самого HAProxy. Если `gitea-proxy-01` выходит из строя, VIP переезжает на `gitea-proxy-02`, который продолжает балансировку по той же логике.
* **Gitea Nodes**: Являются целевыми объектами (backend) для HAProxy.

## Пример использования (Example Playbook)

```yaml
- name: Deploy Gitea Proxies
  hosts: gitea_proxies
  become: yes
  roles:
    - role: haproxy
      tags: haproxy
    - role: keepalived
      tags: keepalived

```
