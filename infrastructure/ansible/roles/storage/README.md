# Описание роли: storage

Роль предназначена для развертывания службы сетевого хранилища на базе **NFS-Ganesha** (User-Space NFS Server). Обеспечивает единую точку монтирования (Shared Storage) для данных приложения Gitea (Git-репозитории, артефакты), что критично для конфигурации кластера Active-Active/Active-Passive на прикладном уровне.

## Требования (Requirements)

* **ОС**: Ubuntu/Debian.
* **Keepalived**: Требуется предварительная настройка роли `keepalived` на узлах хранилища для управления плавающим IP-адресом (VIP), к которому будут подключаться клиенты.

## Переменные роли (Role Variables)

На основе контекста архитектуры и шаблонов ожидаются следующие переменные (определяются в `group_vars`):

| Переменная | Описание |
| --- | --- |
| `storage_vip` | Виртуальный IP-адрес для подключения клиентов (например, `172.20.0.30`). |
| `gitea_data_dir` | (или аналогичная) Локальный путь на сервере хранения, который экспортируется клиентам. |
| `nfs_export_id` | Идентификатор экспорта в конфигурации Ganesha (задается статично в шаблоне). |

## Техническая реализация (Architecture)

### Задачи (Tasks)

1. **Подготовка окружения**:
* Создание необходимых системных директорий для корректной работы user-space демона (`/var/run/ganesha`, `/var/log/ganesha`).


2. **Systemd Override**:
* Внедрение `drop-in` файла в `/etc/systemd/system/nfs-ganesha.service.d`. *Имплементация:* Чаще всего используется для изменения ограничений (limits), привязки к нужным сетевым интерфейсам (`After=network-online.target`) или обеспечения старта только после инициализации VIP от Keepalived.
* Вызов `systemctl daemon-reload`.


3. **Конфигурация экспорта**:
* Генерация конфигурационного файла `/etc/ganesha/ganesha.conf` из шаблона `ganesha.conf.j2`. Настраивает параметры экспорта (путь, права доступа, squash-политики).


4. **Управление состоянием (Lifecycle)**:
* Вызов `meta: flush_handlers` гарантирующая, что служба `nfs-ganesha` будет запущена и применит конфигурацию ДО того, как роль `gitea` попытается примонтировать.
* Проверка состояния службы (`state: started`, `enabled: yes`).



## Взаимодействие с другими компонентами

* **Keepalived**: Обеспечивает отказоустойчивость (L3). Ganesha слушает на `storage_vip`. При падении `storage-01`, VIP переходит на `storage-02`. Клиенты (Gitea) испытывают кратковременное зависание I/O (NFS timeout/retry) до восстановления соединения.
* **Gitea**: Роль `gitea` выступает клиентом. Она монтирует экспорт через стандартный NFS-клиент ядра Linux (`mount -t nfs ...`).


## Пример использования (Example Playbook)

```yaml
- name: Deploy Storage Layer
  hosts: storage_cluster
  become: yes
  roles:
    - role: keepalived
      tags: keepalived
    - role: storage
      tags: storage

```
